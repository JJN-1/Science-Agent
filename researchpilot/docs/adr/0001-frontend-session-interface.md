# ADR-0001: 前端采用会话式单流界面

- 状态：已采纳
- 日期：2026-09-19
- 关联：设计文档 §4.1 界面层；FIX-11

## 背景

设计文档原规划为三页面结构：项目列表页、会话工作台页、设置页，页面之间以路由跳转。

科研流程的实际形态是：一个项目从选题到投稿要经历 8 个阶段、跨数天到数周，
用户的高频动作是「看当前跑到哪了、读最新产出、在需要时批准或干预」，
而不是在多张页面之间切换。

页面拆分带来两处额外成本：
一是研究状态要在页面之间重复加载与同步；
二是实时进度（SSE）与结果渲染分居两页，用户要来回跳。

## 决策

> 我们决定前端采用会话式单流界面：左侧项目侧边栏常驻，右侧为单条纵向流，
> 应用只保留两条路由（`/` 空态、`/projects/:id` 项目会话），设置以对话框承载。

## 理由

- 阶段进度、产出、审批请求同处一条时间线，用户不需要切换上下文即可读完一个阶段的完整过程。
- 单路由 + 单页持有研究状态，减少跨页面状态同步与重复请求。
- 侧边栏常驻，项目间切换等价于换一条流，切换成本恒定。
- 设置属于低频、短时动作，模态对话框足够，不占用路由与页面级状态。

## 与设计文档的差异

| 设计文档 | 实际采用 |
|---|---|
| 三页面结构（项目列表 / 会话工作台 / 设置） | 侧边栏 + 单流，仅两条路由 |
| 设置为独立页面 | 设置为模态对话框（`SettingsDialog`） |

## 后果

### 正面

- 长时程任务的上下文连续，进度与产出同一视觉锚点。
- 前端状态源收敛到单一页面组件，SSE 订阅生命周期清晰。

### 负面 / 代价

- 单页组件承担较多职责，需要靠子组件（`CommandBar` / `RunBlock` / `ApprovalCard` / `Markdown`）拆分维持可读性。
- 流内内容增长后需要处理滚动与自动定位，长会话的渲染量高于分页方案。

### 需要跟随的动作

- 设置页将来若出现多标签、多分区需求，需评估升级为独立路由。
