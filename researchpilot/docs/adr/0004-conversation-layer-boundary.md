# ADR-0004: 对话层与结构化黑板的职责边界

- 状态：已采纳
- 日期：2026-09-19
- 关联：设计文档 §9 / §16；US-304；ADR-0001

## 背景

界面是会话式的（见 ADR-0001），用户输入自然会表现为一条条消息。
如果直接把「对话历史」当作研究状态的存放处，会出现三个问题：
一是研究产出散落在自然语言里，无法版本化与比对；
二是对话一旦截断或压缩，研究状态随之丢失；
三是阶段之间传递的输入变成「读上一条消息」，缺乏校验与溯源。

项目已存在结构化存储：黑板（`blackboard`，按 `obj_type` + `version` 存放产出）
与检查点（`checkpoints`，阶段级快照），并有证据锚点（`evidence`）机制。

## 决策

> 我们决定：研究状态的唯一权威是黑板与检查点；对话层只承载交互意图与展示，不持有研究状态。

具体边界：

| 归属 | 内容 |
|---|---|
| 黑板 / 检查点 | 阶段产出、版本、证据锚点、审批结论 |
| 对话层（会话 / 消息） | 用户输入、系统提示、对产出的展示性引用 |
| 执行轨迹 | `agent_steps` + `job_events`，按 `run_id` / `job_id` 归属，不进对话历史 |

对话中的产出一律以**引用**形式出现（指向黑板对象 id / 版本），不复制正文作为状态副本。

## 理由

- 研究产出需要可溯源、可版本化、可复现，这三者都要求结构化载体而非自然语言载体。
- 对话可清空、可压缩、可重新生成，而研究状态必须稳定，两者生命周期不同，不能合并存储。
- 阶段输入从黑板读取并做 schema 校验，避免把上一阶段的自然语言原样透传。
- 执行轨迹按 `run_id` / `job_id` 归属，才能支撑失败现场回放与作业级排查。

## 与设计文档的差异

无。

## 后果

### 正面

- 对话历史可以安全地裁剪或重建，不影响研究连续性。
- 阶段间传递有明确契约（`obj_type` + schema），可做校验与降级。
- 每个产出都能追到证据与产出者。

### 负面 / 代价

- 前端需要在两种表示之间做转换：流内的展示性文本 vs 黑板对象引用，组件要多一层解析。
- 对话内容与黑板对象可能出现「显示的是旧版本」的错位，需要显式渲染版本号。

### 需要跟随的动作

- 对话层建表（`conversations` / `messages`）时，消息不得内嵌产出正文，只存引用。
- 阶段上下文组装统一从黑板读取，禁止从对话历史取数。
